# P1/P2 Repository Cleanup Implementation Plan

> **For agentic workers:** Execute each task with a focused verification gate before the next task.

**Goal:** Close deployment, documentation, generated-file, and verification gaps while preserving recommendation behavior.

**Architecture:** Keep the bundle-backed application path canonical. Package `application`, `api`, `common`, `infrastructure`, `logger`, `retrieval`, `serving`, and the immutable bundle in the Lambda image; keep training/data code out of runtime. Treat CI as responsible for proving the bundle exists before the image build.

**Tech Stack:** Python 3.10, FastAPI, pytest, Ruff, Docker, AWS SAM, Next.js frontend, GitHub Actions.

## Global Constraints

- No recommendation algorithm or model-artifact contract changes.
- No secrets or large model payloads committed.
- Generated files are removed only when reproducible and not required fixtures.
- Network/build failures are reported as blockers.

### Task 1: Lambda packaging contract

**Files:** `backend/Dockerfile.lambda`, `backend/tests/unit/test_lambda_dockerfile.py`

- Add `COPY backend/application/ ${LAMBDA_TASK_ROOT}/application/`.
- Extend the test path list with `application/`.
- Run Ruff and the focused Dockerfile test.
- Commit `fix: package application layer in lambda image`.

### Task 2: CI bundle preflight

**Files:** `.github/workflows/deploy.yml`, `backend/tests/unit/test_lambda_bundle_packaging.py` (or the existing bundle packaging test)

- Keep the current explicit `MODEL_BUNDLE_PATH` contract.
- Add a clear preflight that checks `bundle_manifest.json`, `ranker/model.txt`, and all four retriever manifests before Docker build.
- Add a test asserting the workflow performs these checks and passes `MODEL_BUNDLE_PATH` to Docker.
- Run focused tests and commit `ci: validate model bundle before lambda build`.

### Task 4: Generated-file policy

### Task 5: End-to-end verification
